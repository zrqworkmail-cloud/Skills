# 可编辑制作与验收

## 模板复用

- 从模板副本中选择现有正文布局，保留母版、主题、徽标和页脚。复杂母版上的对象未必能直接从单页 shapes 读取。
- 删除或复制幻灯片必须正确处理关系文件。不要假定 slide 文件编号、显示顺序、notesSlide 编号相同。
- 若不得不用库的私有 API，应隔离代码、记录版本并验证关系完整性，不能承诺跨版本兼容。
- 原件只读，输出独立版本。检查器只盘点，不修改文件，也不证明关系或 schema 全部有效。

## 构建与结构检查

- 按素材、依赖和模板复杂度选择现有库或 PPTX 技能提供的模板编辑工具；先完成页面复制、排序和删除，再填充内容。保留图表、备注及媒体关系，复制后的图表可能共享数据部件：独立编辑前检查并解除不必要的共享。
- 处理图表时核对原生对象、缓存与实际数据源；有空白模板项时清理整组残留文字与图形，不只删占位文字。检查备注与实际页对应、超出页面的对象及未使用素材。
- 若可用 PPTX 技能的文件验证器，对基于模板的成果同时提供原模板进行差异校验；先检查工具和依赖实际存在，记录返回结果。结构验证不能替代逐页渲染或 Office 应用内测试。

## 真实编辑能力

原生 PPTX 路线：标题和正文用文本框，表格用原生表格，实验图表优先用原生图表并保留数据源。检查生成文件中的文本对象、chart 关系、数据缓存及适用时的嵌入工作簿，不能只数图片。
复杂概念图可以使用 GPT Image 位图，但要明确其局部不可编辑。只有用户接受混合交付时才采用，不把整页扁平化后称“完全可编辑”。

代码可用于原生形状排版、数据图表及文件结构操作。用户要求 GPT Image 画流程图时，先讨论布局与技术内容，再调用图像生成；不要改用代码生成 PNG 流程图。整页 PNG 模式不适用原生对象验收。

## 数据与学术表述

- 数值来自可核查材料，不让生图模型填造。图表缓存、工作簿、文字说明与源数据保持一致。
- 标明误差指标的优劣方向、单位、预测长度和聚合口径。缺失值保留缺失，不补造。
- 同时比较原模型 Baseline 与相应控制臂，报告绝对差值及相对变化，不只挑有利结果。
- 柱状图原则上从零开始；不同面板纵轴范围不同时注明，不能跨面板比较柱高。
- 单 seed 写成探索性信号；均值不隐藏个别预测长度退步，协议不同的结果不声称公平胜出。
- 演讲备注写入 PPTX 内部并按真实 slide 关系关联，可记录完整口径和局限。

## 科研汇报与答疑

- 先用一页总览交代研究问题、近期做了什么、主要发现和下一步，再按主题展开；页序、信息密度和详略服从听众、时长与用户要求，不强制套用固定页数。
- 对每项主要方法或实验，尽量用通俗语言说明“为什么做、是什么、怎么做、和对照有什么区别、结果意味着什么”；术语首次出现时简释。对照组说明具体保留与改变的部分。
- 当用户需要上台讲解或准备答疑时，提供与页码对应的演讲备注或讲稿，并标注证据、口径、尚未解决的问题和可能追问；不为不存在的结论编造答案。必要细节放附录或备注，主体保持可读。

## 公式与实验表格

- 用户要求可编辑公式时优先采用 Office Math（OMML）等可在目标 PowerPoint 环境编辑的原生数学对象；保留可追溯 LaTeX 源，不能把普通文本或公式图片称为原生可编辑。兼容预览可辅助显示，但不代替编辑能力验证。
- 按数学语义排版：变量通常斜体，说明性下标、函数名与运算符通常正体，注意上下标、括号及符号；同一张表的公式主体与表格字号协调，上下标可按数学排版缩小。遵循用户或目标刊物规范，不将某种字体和字号设为所有项目的硬约束。
- 在指标方向明确且比较协议相容的结果表中，可按用户要求对最佳值加粗、次优值加下划线。先按原始精度判断，说明并列的处理；缺失值标记缺失，不参与排名。协议不相容时不混排，不伪造排名；四长度均值仅在口径一致且数据齐全时计算。
- 逐项核对表格数字、最佳/次优标记、均值与原始来源；视觉预览、OOXML检查与实际PowerPoint内打开及编辑是不同验证层级。未进行应用内验证时明确说明。

## 字体与动态字段

按模板设置字体，而非固定所有项目用某一种字体。中文同时检查东亚字体属性，图表标签单独核对。字体名存在不代表渲染时真正使用了该字体。
渲染后可用 PDF 字体信息核查替代情况；必要时只在本次进程启用字体路径，不改系统或科研环境。不打包、上传未经授权的商用字体。

日期和页码 `a:fld` 可能被渲染软件重新计算，缓存里的日期/页号不能作为最终显示证据。
若用户要求固定样页编号，可在输出副本中将目标字段转换为普通文字 run，保留其文字和 run 属性；不能把所有字段一律转换。正式整套另行统一页码策略。

## 渲染与 QA

本地可选依赖为 python-pptx 或 PptxGenJS、LibreOffice、Poppler/PyMuPDF；按已有能力选用，不要求全部安装。

LibreOffice 示例，使用独立临时配置避免与现有进程冲突：

```bash
ppt_profile=$(mktemp -d /tmp/ppt-render-profile.XXXXXX)
libreoffice "-env:UserInstallation=file://$ppt_profile" --headless \
  --convert-to pdf --outdir <输出目录> <输出.pptx>
pdftoppm -png -scale-to 1920 <输出.pdf> <输出目录>/page
```

占位符需替换为实际路径，路径带空格时加引号。没有成功返回、没有实际输出文件时，不声称转换成功。临时目录保留至排查完成，按环境的临时文件策略回收。

验收顺序：

1. 核对模板哈希未变、输出不覆盖原件。
2. 检查 PPTX 可读取、页面顺序、关系完整性、原生对象与关键数值。若有 schema 验证器则运行并记录，不将 ZIP 可读当成完整验证。
3. 重建全部最终预览，先用缩略图总览检查整体节奏，再实际逐页检查可读性与细节；不是只读 XML 或只看缩略图就宣布无溢出。
4. 检查字体替换、遮挡、裁切、图表文字、页脚、图例、留白与投影可读性。
5. 有 Office 应用内检查能力时验证编辑与打开；未做则明确写“未在 PowerPoint 应用内验证”。

交付说明列出文件、可编辑范围、检查结果、已知限制。结构正确、渲染美观和 Office 兼容是不同层级的证据。
