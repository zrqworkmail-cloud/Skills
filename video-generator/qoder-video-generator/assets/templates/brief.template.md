## Duration：先编辑，再算下限

不设目标镜数，不用 BGM 决定内容。无统一时长上限也不意味着无需删支线：每段都要兑现承诺。

- `read`：字幕按舒适 5.5、硬上限 7.2 单位/秒（与 `caption_fit.py` 同口径）加呼吸，再计无字幕演示时间。
- `voice`：已录语音实测时间加余量；额外演示停顿要落实到时间线。
- 阅读下限不是理解时间；看图、预测和比较的停留由样片验证。必须压缩时，由创作者决定删哪些内容。

```bash
# 无音乐可独立执行；<tools> 换实际工具路径，在项目根目录运行
python -X utf8 <tools>/plan_duration.py --mode read --text spec/narration.txt \
    --extra-s <无字幕演示秒数>
# 有配音改用 --mode voice --timing audio/narration/timing.json
# 已分析用户自备音乐后，按需附加 --fit-music build/bgm_analysis.json
```

结果只在 `spec/duration_plan.json`。配乐拟合向上取整小节，装不下会拒绝；循环、换曲、删字需批准，不能静默改变。

## Cut grid 与音轨

- `bar`：切点按小节，审计强判；`caption`：按内容／句子剪，小节偏差只报告，不要求一句一切。
- `remotion`：最终渲染内嵌音轨；`post_mux`：先静音渲染，再 stream copy 封装，每次重渲都要重封。
- `none`：确实无音轨，不伪造音床。音乐未定可先交明确标注的静音版，不能冒充有声定稿。
- 音乐后到不拉伸画面凑小节；固定阅读字幕、因果过程和声音共同审节奏。

同步到 `shotlist.json` 的 `cut_grid` 与 `audio.mode`，工具读那份。是否有旁白／去人声按本片决定；用户自备配乐绝不擅自替换。
