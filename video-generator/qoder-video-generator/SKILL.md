# Qoder 视频产线（v9.2）

## 定位

- 本技能是面向 Qoder / Codex 类 agent 的**本地可执行产线**：以 `references/WORKFLOW.md` 为唯一流程真源，SKILL.md 只作入口，不另立一套阶段、阈值或门禁。
- 每次从实际文件读取当前流程，不凭记忆套用旧阶段、旧路径或旧阈值。流程文档中记载的版本号与实测数字属于历史证据，不等于当前项目的现状。
- 与 `workbuddy-video-generator` 的分工：后者是与项目、工具、素材来源无关的八阶段通用主干；本技能是绑定本地 Remotion / ComfyUI 产线的一版实现，带输入契约、工具脚本与逐项复验。同一任务只选一套，不叠加门禁。

## 使用边界

- 用户或目标项目已指定其他流程时，先读指定入口并保留已批准的决定；仅在用户要求迁移时切换。
- 区分 `SKILL_ROOT`（本技能包所在目录，只提供规范、模板与工具）与 `PROJECT_ROOT`（当前制作项目，默认为会话工作目录）。产出不写回技能包目录。
- 续做先读项目已有的 `BRIEF.md`、`STATUS.md`、`review_log.md`、`spec/shotlist.json`，从已记录阶段继续；不批量迁移旧项目、不重做已完成环节。
- 单项请求（脚本、审片、导出）只做对应阶段，不自动扩成整片制作。
- 未授权不安装依赖、不占用长时 GPU、不产生付费调用、不上传或发布。提交、推送、上传、发布按当次授权分别处理，且只点名本轮文件。

## 开工流程

1. **读流程**：打开 `references/WORKFLOW.md`，先读 §0 确定两个根目录，再按 §9「按任务读取契约」决定本轮需要哪些章节。
2. **核能力与证据**：按 S0 枚举当前可用工具与参考证据，不使用未经核实的引擎能力；`scripts/env_report.sh` 是只读探针，其报告只覆盖它实际检查的路径与依赖。
3. **先定内容**：按 S1 填写 `assets/templates/brief.template.md` 与 `frame.template.md`，明确受众问题、承诺、内容取舍与声音路线；不先定工具再凑内容。
4. **剧本与分镜一起设计**：按 S2–S3 填 `assets/templates/shotlist.template.json`。分镜机器真源是 shotlist，时长真源是 duration_plan，STORYBOARD 由生成器派生；不手改派生文件。
5. **完成时间线适配**：按 WORKFLOW §3 产出 beat_timeline 与渲染器时间线，核对帧数与字幕映射一致。未提供通用自动排时器，适配未完成不进入渲染。
6. **样片确认**：先做关键机制的完整画质样片与连续开场，交用户确认后再按批准范围分段展开。未在样片确认前不做全量渲染、不批量生成、不覆盖已有成果。
7. **装配与评审**：按 S7–S9 记录报告、覆盖项与未审项。生成器里的 `animated` 标签不构成审批。
8. **交付复验**：在交付 MP4 上逐项核对帧数/时长、视频流与静音母版一致、faststart、响度与真峰、逐 cue 平衡与对位、安全区与字幕带、首帧亮度、音频起点 0；缺项写「未验」，不用其他文件的数字顶替。

## 验收三层（不可互相代替）

| 层次 | 要回答的问题 | 证据 |
|---|---|---|
| 内容与观看 | 观众为什么看？画面让他理解了什么？连续观看是否成立？ | 事实来源、机制样片、开场与全片审片记录 |
| 技术可靠 | 有没有冻结、压字、音画错误、资源越界？ | 实际交付文件、工具原始报告与人工复核 |
| 发布效果 | 哪段留住人、哪段误解或流失？下一条改什么？ | 授权取得的实际后台数据、同口径比较；无数据则待验证 |

**技术 0 FAIL 不是审美通过，更不是传播有效。** 亮度、压字等检查多为「仅报告、需人工复核」；部分检查绑定固定画幅或历史镜头口径。

## 脚本使用约定

- `scripts/` 是**参考实现**，不是开箱即用的安装器。运行前在目标环境实际执行一次 `ffmpeg -version` 等能力探测；依赖缺失时报告，不自动安装。
- 外部二进制一律走环境变量或运行时探测，不写死绝对路径：`FFMPEG` / `FFPROBE`（或 `FFMPEG_PATH`）、`PY`（Python 解释器）、`COMFY_WORKFLOW_TEMPLATE` / `COMFY_OUTPUT_DIR`（ComfyUI 路线）。
- 命令在 `PROJECT_ROOT` 执行；路径含空格时加引号。Windows 解释器与 Git Bash 的路径写法不同，不从 Windows Python 盲调名为 `bash` 的程序。
- 历史工具与新模板存在不兼容项（如旧 `build_timeline.mjs`），以 WORKFLOW §3 的适配结论为准，不以脚本存在为由跳过适配。

## 创作原则（v9）

- 知识片默认「视觉实验／连续演示」：让同一主体跨句推进，文字与画面一起设计。纸面档案降为可选风格，不强制黑底金字、粒子或某个视频模型。
- 不为过帧差阈值补动作、不设 hold 必须微动、不设固定动作时点配额。保留测量，但测量服务于观看，不替代观看。
- 用户自备音乐不替换、不生成、不拿 TTS 顶替。
- 用户观感优先于质检通过；QC 结论与人眼审片结论分开记录。

## 来源与脱敏

本技能由 `knowledge-video-workflow` 来源仓的 v9.2 流程文档整理而成。公开版本已移除本机绝对路径、私有项目规格、生成媒体、构建产物与凭据；脚本中的外部二进制改为环境变量或运行时探测。原始工程实现、成片与项目状态仍留在来源仓，不随本技能分发。
