## 1 · 动效：保留数字，撤销过度推论

### 1.1 整帧平均帧差对细线不敏感，不等于细线没解释力

**历史证据**：overfit v2 有 8 镜超过 `anim` 的 2.0 s 上限：s01 / s07 / s08 / s09 / s15 / s18 / s25 / s29。s25 的章由 26 px 放大到 34 px，峰值帧差从 **0.088** 到 **0.117**，最长静止从 2.97 s 降到 **1.90 s**；测量宽 270 px，冻结线 0.10。

**根因与校正**：测量对变化面积敏感。旧文把它解释成“整帧观感有没有推进”，进而要求细线镜必须补密实章，这是把像素指标当成了创作目标；没有受众证据支持“大章更好懂”。

**当前规则**：取消强制补章、固定尺寸和 55–70% 落点。先看连续片段，区分真实冻结、无效等待与细线漏敏；改画面要为解释服务。确需调整逐镜 `maxHoldS`，保留原报告、给阅读／观察任务依据并经人工确认，不能全片放宽洗掉 FAIL。

**落点**：MOTION §9.1。历史返工记录保留，不以撤销规则为由改写当时测量。

### 1.2 0 FAIL 不等于连续观看成立

**历史证据**：rain-70 v28 为 **58%** 静止帧、11/31 镜超上限；overfit v3 为 **87%** 静止帧、34 镜 **0 FAIL / 1 WARN**。

**根因与校正**：逐镜最长静止上限和全片静止比例是不同量。短动作可以切断长静止段而几乎不改变总体比例；这不证明观众得到了有意义的落点。相反，必要的四秒阅读也不必然让人误以为卡住。

**当前规则**：如实报告静止比例，不加装饰性运动降数；高静止不是自动缺陷，也不是风格豁免。内容、连续观看与发布效果分别检验。

**落点**：MOTION §8–10；WORKFLOW §6、§14。

### 1.3 事件后的等待，要按观众任务处理

**历史证据**：overfit 失败镜的曲线多在前 1/3 长完；把补章放在 56–64 帧／84–107 帧（约 60–67%）可切开静止段。

**根因与校正**：这验证了检测器量“最长连续静止”，没有验证这个位置是最佳揭示点。旧规则要求动作兼任“切开静止段”，诱导了无关动作。

**当前规则**：时间按条件准备、预测、变化、结果比较与阅读分配。无任务等待应删或重设计，必要观察可以 hold；同一因果链可有多个连续步骤，不要求一镜只动一次。

**落点**：MOTION §2、§5；shotlist 的 visual／intent 共同说明信息与时点。

### 1.4 保护阅读字幕，不禁止文字承担演示

**历史证据**：overfit s25 的“双拍字幕”因读字干扰被回退，最后改用章。这是该镜返工经历，不证明所有文字变化都不合适。

**当前规则**：固定阅读字幕保持位置、大小与对比稳定；填空、换位、替换等文字本身是演示对象时可按设计变化。禁止为过帧差线闪字，不强制改成旁边落章。需要手机尺寸 1× 连播确认，字幕中点抽帧不能替代这项审查。

**落点**：MOTION §5、§10。

## 2 · 配乐

### 2.1 切点听谁的，必须在 S1 写死

**证据**：

- `rain-70`：音乐先到（112.906 BPM，70 小节），28 条字幕按小节重排，切点钉在小节线上，审计全绿。
- `overfit`：画面按字幕节奏先剪完，音乐后到。**33 个内部切点全部不在小节线上**；
  按小节线量，中位偏差 **474 ms**，只有 **3/33** 落在 ±80 ms 内。`audit_music_cut.py` 报 33 problems。
  （旧记录里的 139 ms / 11/33 是拿**拍**网格量的：拍间隔 534 ms，离最近的拍当然更近；
  审计按小节量，这个区别在复盘时被量出来了。）

**根因**：切点同时受“句子读完”和“小节线”两个约束。两者只在 S1 同时可见时才能一起解；
画面先冻结、音乐后到，就只剩“重剪重渲”或“承认不对齐”两个选项。

**规则**：

- `shotlist.json` 顶层声明 `cut_grid`：
  - `bar`：音乐先到，切点钉小节线，审计把偏差当 FAIL。
  - `caption`：画面按句子剪，音乐后到，审计只报告偏差，不当 FAIL；交付说明里写清缺口。
- **音乐晚到不是把画面拉长、缩短、变速去凑小节的理由。** 拉伸会让字幕节奏与运动全部失真，
  比“切点差半秒”更伤。
- 真要卡点，就是重剪切点 → 重排字幕 → 重渲 → 重跑动效闸门，四件事一起做，不是顺手改一两个镜头。

**落在哪**：`WORKFLOW.md` §2；`assets/templates/shotlist.template.json` 的 `cut_grid`；
`scripts/audit_music_cut.py` 的两种模式。

### 2.2 音乐晚到：post-mux，不重渲画面

**证据**：`overfit` 交付时画面已经是 v3 静音母版。封装后视频流 md5
`46f6c49e…` 与母版**逐字节相同**；音轨从 0 开始，音画偏移 **0 样本**；交付 14,917,525 B；
AAC 256k / 48 kHz / 立体声，实测 265 kbps。

**根因**：声音是音频流，不是画面像素。只要音床长度与画面严格一致，容器层封装即可，
没有任何理由为了加声音再编码一次 H.264。

**规则**：

- `audio.mode: post_mux`：画面静音渲染 → 音床做好 → `mux_music.sh` 封装（`-c:v copy`）。
- 封装脚本必须自己验四件事：**音床与画面等长（±0.05 s）**、**视频流 md5 不变**、
  **音轨 start=0 且时长一致**、**faststart（moov 在 mdat 前）**。
- 任何重渲之后都要重新封装，否则会退回无声版——这是 `post_mux` 项目最容易忘的一步。

**落在哪**：`scripts/mux_music.sh`；`WORKFLOW.md` §5；`assets/templates/shotlist.template.json` 的 `audio.mode`。

### 2.3 曲子的尾端不能直接贴片尾

**证据**：`overfit` 用的经典 BGM 在 149.999 s 是硬切，尾端仍有 **−8.7 dB**。
交付版在 109.924–111.724 s 做 1.80 s 淡出，之后留 **0.66 s 静音**到 112.3667 s 片尾；
开头 0.30 s 淡入。

**根因**：创作者的曲子往往不是为这部片写的，尾端可能停在半个和弦或一刀切上。
直接 `-t 片长` 截断，会在片尾留下一个“被剪断”的爆音或突兀静音。

**当前规则**：音乐收尾按曲式与实际听审决定。片尾前 0.5–2 s 淡出、留 0.3–0.8 s 静音、片头淡入 0.2–0.4 s 是这类历史配方的起步值，不是所有曲子的硬要求。音频淡化不自动要求画面一起变暗。

**落在哪**：`scripts/mix_music.sh` 的 fade 逻辑；`mux_music.sh` 只负责封装，不替创作者改音床。

### 2.4 剪接先看和声，再看结构

**证据**：`overfit` 的曲子是 112.347 BPM、小节 2.1362 s、70.216 小节；片子只有 52.6 小节，整条铺不下。
剪法：取 `0 → 55.867 s`，接 `94.122 → 149.999 s`，20 ms 等功率交叉淡化。
末段正拍落在画面 56.381 s，离 59.0 s 的“转”幕切点还有 2.6 s；没有把抬点推到幕切点，
因为 58.5 s 处与末段的 chroma 相似度只有 **0.24**（会撞调），而 55.867 → 94.122 这条接缝是 **0.977**。

**根因**：接缝能不能听出来，第一决定因素是和声/配器是否连续，第二才是结构位置。
为了“幕切点对齐”硬接一个不同调的位置，会得到一个明显的调性跳变。

**规则**：先按拍（小节线前最后一拍）找候选接缝，再算接缝两侧的 chroma 相似度；
优先选相似度高（≥0.9）的，结构位置可以让 1–3 s。接缝用 10–30 ms 等功率交叉淡化，
并在交付说明里写清“为什么没对齐幕切点”。

**落在哪**：`overfit` STATUS §3；`scripts/audit_music_cut.py` 的小节网格；`analyze_bgm.py` 的段落输出。

### 2.5 只量 WAV 不算交付

**证据**：`overfit` 的音床剪好是 −10.08 LUFS / TP +0.40 dBFS；两遍线性 loudnorm 后
WAV 约 −13.9 LUFS；封装成 AAC 后交付文件实测 **−14.0 LUFS / TP −2.7 / LRA 3.0**。
曾多加一个 `volume=-0.1dB`，交付变成 −14.1，最终去掉、重封，才回到 −14.0。

**根因**：AAC 编码会轻微改变响度与真峰值；在 WAV 上调到“看起来对”，封装后可能差 0.1–0.3 LU。
用手调音量去补，会把误差带进下一版。

**规则**：响度**只在最终交付文件上量**；`mux_music.sh` 封装后立即跑 ebur128。
目标 −14 LUFS（允许 ±0.5）、TP ≤ −1 dBFS。WAV 阶段只保证不削波，不做最终判定。

**落在哪**：`scripts/mux_music.sh`；`scripts/gates.sh` 的响度闸门（现在会 FAIL，不再只打印）。

### 2.6 `atrim` 的 sample 参数按“输入采样率”算

**证据**：在 44.1 kHz 输入上写 `atrim=end_sample=5393600`（本意是 48 kHz 下的 112.3667 s），
得到 **122.3 s** 的音床——多出 10 秒。改为在重采样前按秒截断 `atrim=end=112.366667`，
再 `aresample=48000`，长度才对。

**根因**：`end_sample` 的单位是当前流的采样点数，不是目标采样率下的点数；滤镜链顺序一变，含义就变。

**规则**：跨采样率的裁剪一律用**秒**（`atrim=end=<seconds>`），并且先裁后重采样；
需要样本级精确时，先重采样到目标率，再算 `end_sample`。裁完必须 `ffprobe` 复核时长。

**落在哪**：`scripts/mix_music.sh` 的注释与实现。

## 3 · 闸门工程

### 3.1 打印不等于失败

**证据**：旧版 `gates.sh` 把 `ebur128` 的结果 `grep` 出来就结束，没有数值判断；
`audit_music_cut.py` 的退出码被 `| tail -12` 吞掉。结果是闸门日志最后打印
“所有闸门通过”，而同一次运行里卡点审计其实报了 33 个问题。

**根因**：把“测量”当成了“验收”。测量只产生数字，验收必须把数字与判据比较，并把失败汇总进位。

**规则**：声称是自动硬门禁，就必须同时有明确判据、越界汇总和非零退出码；只能报告的工具要明确标为人工复核项。保留完整日志，不凭末尾一句话判全部通过；管道退出码必须正确传递。

**落在哪**：`scripts/gates.sh` 已接入响度、音轨、卡点审计、封装一致性与 motion 的失败；**不代表所有检查已自动化**。见 §3.5 与 WORKFLOW §6。

### 3.2 证据路径必须只有一个主人

**证据**：`render.sh` 把 CPU 采样写到 `build/cpu_<tag>.csv`；`gates.sh` 却去
`build/gates_<tag>/cpu.csv` 找。文件永远不存在，于是每次渲染的“over80 样本数”
在闸门汇总里静默缺失——不是没采，是没人读。

**根因**：同一个产物被两个脚本各自命名。路径不是接口，却当成了接口。

**规则**：一个产物只有一个写入者、一个默认路径；读取方要么读那个路径，要么接受显式 `--cpu`。
找不到样本不是“通过”，要在汇总里报 WARN 并写清去哪找。

**落在哪**：`scripts/gates.sh` 的 `--cpu` 与默认路径 `build/cpu_<tag>.csv`。

### 3.3 端口 3134 的遗留进程会污染下一次渲染

**证据**：被终止的代理任务留下 Remotion 子进程继续持有 3134；下一次 `render.sh`
要么连到旧 Studio（拿到旧代码的帧），要么直接在启动阶段失败。
`render.sh` 的注释里记着这件事，但脚本本身没有预检。

**根因**：Remotion 的 Studio/渲染进程是进程树，杀父进程不保证杀子进程；端口是全局资源。

**规则**：渲染前检查 `LISTENING`，打印占用 PID 与进程名，**退出 2，不自动 kill**。
只结束自己确认过的遗留进程；不是自己启动的进程，不碰。

**落在哪**：`scripts/render.sh` 的 preflight。

### 3.4 审计要分模式，不能把“声明过的选择”当故障

**证据**：`overfit` 是 caption-led 片子，`audit_music_cut.py` 仍按 bar 模式判，
33 个切点全记 problem，还因为音轨在后期封装而报 `mix.wav missing`。
这两个“问题”都不是混音错误，是审计不知道这部片的契约。

**根因**：审计把一种剪法（音乐先到）当成了唯一剪法。

**规则**：审计读 `cut_grid` 与 `audio.mode`；`bar` 强判小节对齐，`caption` 只报告小节偏差，其他契约错误仍须处理。不是所有“声明过的模式”都只报不判。不要为了变绿去改阈值或伪造 mix.wav。

**落在哪**：`scripts/audit_music_cut.py`；`WORKFLOW.md` §2、§6。

### 3.5 v9 源码诊断：仅报告与覆盖不足仍然存在

**本轮证据（非成片重测）**：`luma_report.py` 打印 >25 的切点数量与首帧亮度，不因越界返回失败；`plate_swing.py` 只打印、且只遍历雨片的固定镜头 ID；`safezone_check.py` 与 `text_zone_check.py` 报疑点但无质量失败退出码。`gates.sh` 给它们加 `|| note_fail` 只能捕获程序错误，不能让报告自动变成质量门禁。CPU 超限、字号估算和中文扫描也不能靠最后的汇总证明合格。

另：`make_storyboard_md.py` 写死 `status: animated`，生成分镜不等于该镜已建造或已审批。

**根因**：接口能运行、测量有输出、结果可自动判定、覆盖了全部对象，是四件不同的事。旧文把它们统称“全部闸门”，掩盖了审查缺口。

**当前规则**：按实际源码列机器真判／仅报告／人工审片；缺覆盖或待审会阻止“可发布”结论。分镜实际批准状态只认 `review_log.md`。v9 本轮仅修正文档，不宣称这些代码缺口已修复；以后自动化须另做测试。

**落点**：WORKFLOW §3、§6–7。

## 4 · 交付

### 4.1 所有数字量在最终 mp4 上

**证据**：`overfit` 交付件的实测：首帧 YAVG **114.3**、安全区距底 **370 px** / 距右 **193 px**、
31 句逐镜中点抽帧压字 **0 offender**、34 镜 **0 FAIL / 1 WARN**、响度 **−14.0 / TP −2.7**、
音画偏移 **0 样本**、faststart、14,917,525 B。
`rain-70` v31：150.016 s / 4500 帧、响度 −14.0 / TP −3.2 / LRA 3.2、安全区 367 / 142。

**根因**：静帧、源码、预览窗口都不会暴露编码后的亮度、裁切、音画偏移与容器布局。

**规则**：交付说明里的每个数字都要能指到一次成片测量；换封装、换音轨、换码率之后**重跑闸门**。
不许把上一版的数字抄到这一版。

**落在哪**：`scripts/gates.sh`；项目 `STATUS.md` 的实测表。

### 4.2 实际输出是 `yuvj420p`，不要“修正”它

**证据**：`rain-70` 与 `overfit` 的交付文件都是 **yuvj420p**（pc / bt470bg，全范围）。
`render.sh` 传的是 `--pixel-format=yuv420p`，Remotion/ffmpeg 这一路输出仍是全范围标记。

**根因**：像素格式是编码器与色彩范围标记的组合；`yuv420p` 是采样方式，`yuvj420p` 是
“同一采样 + full range”的旧标记。播放器按标记解释，颜色是对的。

**规则**：不要在交付前二次转码去把 `yuvj420p` 变成 `yuv420p`；那会多一次编码，
还可能改变亮度。文档按实测写，不按“应该”写。

**落在哪**：`WORKFLOW.md` §7；`overfit` STATUS 的“像素格式别按旧文档改”。

### 4.3 首帧与独立封面不能混为一谈（v9 校正）

**历史证据**：overfit v3 首帧为报纸头版，YAVG 114.3；rain-70 的首帧也不是黑场。这证明两片的设计与亮度，不证明平台要求所有视频首帧均值 >60。

**根因与校正**：旧文把“开播时的第一幅画面”与“列表／投稿选择的封面”混成同一对象，又把整帧平均亮度当成局部信息的可读性。暗底上清楚的大字并不等于空黑帧。

**当前规则**：首帧呈现可辨识的主体／信息，不让观众无信息等待；独立封面按当前投稿入口另验。取消普适亮度 >60 要求，保留局部对比、实际手机尺寸和连续开场审查。

**落点**：WORKFLOW §6 S9；MOTION §4。

### 4.4 CPU 账要每次渲染都报

**证据**：`rain-70` 交付渲染 214 样本，**over80 = 0**（mean 40.9% / p95 54.3% / max 72.4%）；
`overfit` 静音母版 119 样本，**over80 = 0**（mean 31.2% / p95 42.9% / max 51.0%）。
并发固定为 1；提高并发是决定，必须重新测量。

**根因**：渲染是这台机器上最容易越线的负载；没有带外采样，任务管理器里的瞬时数字会说谎。

**规则**：每次渲染都带 `render.sh` 的 CSV 采样，交付说明写 **over80 样本数 / 总样本数**，
不能只写“没超过”。找不到样本要报 WARN，不能当 0。

**落在哪**：`scripts/render.sh`；`scripts/gates.sh` 的 CPU 段；`scripts/cpu_stats.mjs`。

### 4.5 当时投稿入口要求双封面与满幅，不等于视频暗场被禁

**历史证据（overfit v5 投稿阶段）**：竖封面用 9:16 母版居中裁 3:4，平台提示「封面边框面积过大」。旧版四边 YAVG **24.7–28.9**、整图 134.0；改成纸面满幅后四边 **201.4–205.0**、整图 194.6，提示检测通过。只传竖封面时提示「横/竖双封面缺失」，补上 4:3 后消失。png 偶发被拒，同尺寸 jpg 可过。

**解释边界**：去掉深色桌面边带与检测通过同时发生，但本地测量不能反推出平台内部算法，也不能推出“所有暗色封面／暗场视频都不合格”。

**当前规则**：沿用该投稿入口时备 **3:4 竖封面＋4:3 横封面**，分别满幅排版，现场复核当前要求与结果；其他入口先查规则。边缘 YAVG 只是排查边框的工具，不是平台公开阈值。9:16 视频母版保留，独立封面不反向规定视频整体亮度。

**落点**：项目 `outputs/publish/publish.md` 记录裁切、重生成命令、观察日期与平台反馈。这是平台侧检查，`gates.sh` 不覆盖。

### 4.6 平台富文本：历史隐藏态故障

**适用边界（v9.2 审查补正）**：以下保留当时的操作记录与解释，不能据此断言所有隐藏页面都不可编辑，或某条命令永远可靠。§4.7 后续记录表明不同工具受到的影响不同；本次未重演投稿，不把两次观察外推为统一浏览器机制。

**历史证据**：抖音"作品描述"是 Slate 富文本。内置浏览器面板一关，页面 `visibilityState=hidden`、
rAF 冻结，于是：一次调用里连发多条命令把文本**写乱**（字符跑到开头、字数计数器与内容脱钩）；
`insertText` 里的 `\n` 被直接吃掉；DOM 与模型脱钩后 `selectAll`+`delete` 再也清不干净；
连 trusted 的 Ctrl+A / Delete 都无效。而**单条命令**（整段插入一次、点一个下拉项、传一个文件）全部可靠。

**当时解释**：选区与渲染同步可能受到隐藏页面动画帧暂停的影响；这是对上述故障的解释，不是本次验证过的 Slate 内部实现结论。

**当前规则**：多步编辑前保持页面可见；文本输入优先核对当前专用输入工具及其实际兼容性，每次写后回读。当前内置浏览器 `fill` 接口声明支持 contenteditable，但这不证明它已在此 Slate 表单上实测成功。无法可靠编辑或完成最终核验时交给创作者操作，不盲发。话题是否成立以平台回读的实体为准：可能经粘贴自动规范化，也可能需要从 `#` 下拉选中，不能只凭文本中出现井号判断；活动话题与“关联热点”分别核对。

**落在哪**：`outputs/publish/publish.md` 的「投稿表单当前状态」；本机记忆
`reference-machine-and-cli-quirks` 的同名小节。

## 5 · 本轮方法校正：先解释，再测量，再看真实反馈

**证据类型**：2026-10-28 的现有契约／源码核对、公开作品页面与抽帧、创作者开源方法。详细链接与观看范围集中在 WORKFLOW §14，不另造研究现状入口。

**诊断**：旧流程容易把“文案排完＋补动作＋数值通过”当成出片质量。纸面载体被固定为默认，运动用面积过线优化；虽已有 1× 连播要求，数值通过仍可能掩盖漏审，本轮未核实每次终审的实际执行。流程也缺少发布后的同口径反馈，因此形式稳定不等于解释力或观看效果已获验证。这是流程风险判断，**没有后台数据，不能断言它就是低播放的唯一原因**。

**当前规则**：知识片默认视觉实验／连续演示；让观众先猜、比或看到变化，文字与画面共同设计。同主体跨句演进；纸面、暗场、曲线和文字都可用，选择依据是解释任务而非热点外观。关键机制样片→连续开场→分段扩展→全片审查，按批准范围推进。事实、资源、字幕与最终文件检查保留，不换引擎、不动旧片。

**如何证伪**：在新样片上记录能否复述机制、哪里跟不上；发布后按真实后台字段和相同发布年龄观察。24 h／72 h／7 d 只是复盘安排，不是推荐机制。比较同类试片的一项主要变化，记录题材与曝光等混杂，不把少量自然流量比较说成随机 A/B。

**落点**：开工顺序与验收统一读 WORKFLOW S0–S11；三张模板承担输入，不在这里维护第二份步骤表。v9 传播效果仍待验证。

## 6 · 保留的工程底线

不靠装饰性运动或伪造声明洗掉 FAIL；不拉伸成片凑 BGM；不在 WAV 上判最终响度；重封装后重新测量；不盲目二次转码改像素格式标签；不擅自结束他人进程；不把 BGM、个人路径、成片或构建产物提交进仓库。

平台富文本需要实际可见与交互验证；上传、发布、提交与推送按当前授权分别处理。用户原有未跟踪文件保留，不为“干净状态”清理。测量、人工判断、研究假设和受众效果分别标注，回灌不能把其中一项冒充另一项。
