# 本地视频产线 · 可执行工作流（v9.2，2026-10-29）

**先让观众看懂一个变化，再决定用什么工具把它做出来。** 知识片默认走“视觉实验／连续演示”，纸面档案是可选风格，不再是统一外壳。

这份文件是流程的唯一现状入口。质量分三层，不能互相代替：

| 层次 | 要回答的问题 | 证据 |
|---|---|---|
| 内容与观看 | 观众为什么看？画面让他理解了什么？连续观看是否成立？ | 事实来源、机制样片、开场与全片审片记录 |
| 技术可靠 | 有没有冻结、压字、音画错误、资源越界？ | 实际交付文件、工具原始报告与人工复核 |
| 发布效果 | 哪段留住人、哪段误解或流失？下一条改什么？ | 授权取得的实际后台数据、同口径比较；无数据则待验证 |

**技术 0 FAIL 不是审美通过，更不是传播有效。** 本次改版来自参考研究与旧规则诊断，尚无 v9 新片的发布效果验证。研究来源和观看覆盖见 §14。

动效细则在 [MOTION.md](MOTION.md)，历史实测与被校正的推论在 [LESSONS.md](LESSONS.md)。项目现状只在各自 `STATUS.md`，审片过程在 `review_log.md`；旧片不因流程升级自动返工。

## 0 · 从哪里开始

**S0 参考与能力 → S1 受众问题与内容取舍 → S2 剧本、S3 视觉分镜共同设计 → S4 设计、S5 素材 → S6 关键机制与开场样片 → S7 分段装配 → S8 内容与技术评审 → S9 交付 → S10 收尾 → S11 发布后复盘。**

### 用户级全局入口

本技能包的 `SKILL.md` 是跨项目薄入口，正文仍以本文件为唯一流程真源。默认定位本技能包根目录（含 `references/WORKFLOW.md`）；用户或项目已明确指定其他流程时尊重其选择，不自动迁移旧片。路径失效时停下定位。

区分 **WORKFLOW_ROOT（规范／工具）** 与 **PROJECT_ROOT（当前制作项目）**。新项目未另指定时产出留在当前会话工作目录；续做先读目标项目现状。制作命令在项目根执行，支持 `PROJECT` 的工具再传该绝对路径，不能把媒体和项目状态写回全局入口目录。

宿主沿用当前实际加载的用户级 `qoder-video-generator` 安装副本，不额外创建同名副本。先把旧入口备份到技能发现目录之外，再同步薄入口并核对字节一致。安装位置按当前宿主实际加载路径确认，不猜 `~`；其他机器须确认加载目录和真源位置。入口更新不改 App 设置、不授予额外权限；未重新加载的会话可能仍持有旧内容。

“全局”是调用范围，不是无依赖一键产线；项目级时间线适配见 §3，工程覆盖见 §10。

### 工具调用配方

以下是已有工具的调用配方，不是跳过创作与审片的一键生产命令。先填 [brief](../assets/templates/brief.template.md)、[frame](../assets/templates/frame.template.md)、[shotlist](../assets/templates/shotlist.template.json)。在**项目根目录**执行；`<tools>` 换成本技能包 `scripts/` 目录，尖括号都是待填参数。

```bash
# 0) 只读能力探针：READY / ONDEMAND / BLOCKED
bash <tools>/env_report.sh

# 1) 编辑内容后算阅读下限；无音乐时不传 --fit-music
python -X utf8 <tools>/plan_duration.py --mode read --text spec/narration.txt \
    --extra-s <无字幕演示秒数>
# 有配音：--mode voice --timing audio/narration/timing.json
# 有用户自备音乐：先 analyze_bgm，再按需 --fit-music build/bgm_analysis.json
python -X utf8 <tools>/analyze_bgm.py --bgm <track>

# 2) 扫描实际台词；工具位置以能力探针为准
# 外部剧本技能（来源仓依赖，本包不含），路径按当前宿主实际安装位置填写
python -X utf8 "<external-skill>/scripts/scan_script.py" --file script.txt

# 3) shotlist + 已生成的 beat_timeline → 人看的分镜（不能替代时间线生成）
python -X utf8 <tools>/make_storyboard_md.py

# 4) 已建好代表镜 composition 后，单镜满画质 look-dev；审批范围见 §11
bash <tools>/render.sh --still build/ld.png --frame 90 --comp LD-<name>
bash <tools>/render.sh build/ld.mp4 --comp LD-<name> --frames 0-89
# 开场连续样片按实际时长另设帧范围，不把这 90 帧当作开场审片

# 5) 结构检查 → 获批范围内渲染（带外 CPU 采样）
python -X utf8 <tools>/plate_gate.py
bash <tools>/render.sh outputs/film_v01.mp4 --port 3134

# 6) 仅 post_mux 路线：音床完成后封装，画面不重编码
bash <tools>/mux_music.sh outputs/film_v01_silent.mp4 build/audio/bed.wav outputs/film_v01.mp4

# 7) 最终文件测量；post_mux 必须传静音母版的视频流 md5
bash <tools>/gates.sh outputs/film_v01.mp4 --tag v01 \
    --cpu build/cpu_v01.csv --video-md5 <静音母版的视频流md5>
# remotion / none 路线省略 --video-md5；报告项还须按 §6 人工判读
```

Python 统一带 `-X utf8`，调用 Windows 可执行程序时传 Windows 路径。这台机器的 shell `~` 未必是用户目录；技能目录按 `env_report.sh` 的探测结果定位，不猜安装位置。

上述工具有历史实跑记录；**v9 没有重跑渲染或改变工具实现**。新加的样片、内容审查与发布复盘是人工流程，不宣称已被脚本自动执行。

## 1 · S0 开工前：参考研究与能力枚举

### 先研究表达，不先挑特效

围绕相近的观众问题找参考，兼看不同风格与普通表现的作品，避免只挑爆款封面。记录在项目 `BRIEF.md` 的参考表里：链接、作者、发布时间、观察时间、时长／画幅、公开指标的字段名、具体借鉴动作、观看覆盖（全文／连播／听审／抽帧／二手拆解）。

先问：**开头给了什么可验证的承诺？哪个主体持续变化？观众在哪一刻猜、比、数或发现反例？最后如何兑现？** 再看字体、灯光、音乐。黑底金字、粒子、某个模型名都不是效果保证。公开点赞不是留存率，搜索摘要、帐号总赞与单片赞不能混用；没有播放分母就不算互动率。

借鉴方法不等于取得素材许可。下载、转载或生成使用仍需核对版权与当前授权。抽帧不冒充连播，页面文字／章节摘要不冒充视频原话；无法观看的部分明确记“未审”。

### 再核对今天能运行什么

`scripts/env_report.sh` 是只读探针，v9.1 按 `PROJECT`（优先）或调用者当前目录核对 Remotion／recipe；使用时先确认目标项目。BLOCKED 只表示该探针条件未满足，不能外推其他项目都不能运行；所需能力缺失不写成已就绪，确需安装时按 L4 单独批准。ImageGen 在 shell 中仅列 ONDEMAND，工具可用性、调用结果和额度仍须按当前会话核实，不把静态名称当实测。

## 2 · S1 简报：先取舍内容，再计算时长

先在 `BRIEF.md` 写清四件事：**谁有哪个具体疑问、他的已有直觉、这一片只兑现什么、最小可演示的机制是什么**。题目不能只有抽象名词。把必要证据、帮助理解的例子、可移到补充资料的背景分开；每段都要对兑现承诺有用。

时长是编辑后的内容与演示的结果，不是 BGM 或镜数的目标。没有通用的“越短越好”，也不能以“无上限”为由保留所有知识。

| 来源 | 何时用 | 计算下限 |
|---|---|---|
| `read` | 无配音，文字承担解说 | 每句按舒适 5.5、硬上限 7.2 单位/秒（与 `caption_fit.py` 同口径），加呼吸与无字幕演示时间 |
| `voice` | 已有录音 | 实测语音时间 + 呼吸余量；额外演示停顿须落实到时间线 |

读字下限**不包含全部推理成本**：观众还要看图、比较、猜结果。样片读不完或跟不上时，优先删支线、拆解释或延长必要停顿，不加速字幕蒙混。客户／平台秒数写进 Constraints；必须压缩时，由创作者决定删哪些内容。

配乐是可选拟合层：`--fit-music` 向上取整到整小节，不向下截字。曲子装不下会 REFUSE；循环、换曲、删字都需创作者同意。BPM 机器测量允许人工确认值覆盖，但必须记录依据。

产物 `spec/duration_plan.json` 的 `mode / fps / content_min_s / duration_s / frames` 是片长真源；有音乐时附 `music` 拟合结果。后续阶段读它，内容变动后重算，不另造时长来源。

**切点与声音在剪第一刀前声明：**

| 字段 | 取值 | 含义 |
|---|---|---|
| `cut_grid` | `bar` / `caption` | `bar` 强判切点小节对齐；`caption` 按内容／句子剪，小节偏差只报告 |
| `audio.mode` | `remotion` / `post_mux` / `none` | 渲染内嵌 / 静音渲染后封装 / 无音轨 |

`caption` 不等于必须一句一切，也不等于声音节奏可以不审。音乐后到不许拉伸成片去凑小节；要改变剪法，就一起重排切点、字幕和动作，再重渲复审。无配乐的 `none` 路线不伪造卡点数据。

历史例：`overfit` v3 的 33 个内部切点相对小节中位偏差 474 ms，3/33 在 ±80 ms 内；旧记录的 139 ms 是**拍**网格，不可混用。该数只是旧版经验，非当前项目状态、非“必须卡小节才有效”的证据。

## 3 · S2 剧本与 S3 分镜：一起设计，而非写完稿再配图

知识片优先从**一个可操作的例子**开始：让观众先猜／比较／看到矛盾，再把关键变化演出来，随后解释与命名，最后回到开头的问题。不是固定三幕百分比，也不是强制先讲生活哲理。

开头先写不同信息策略的候选，例如“当场猜结果”与“直接展示反例”，而非同一句悬念换三种措辞。选能够在本片兑现的一种，不用夸大的“颠覆认知”代替问题。

### 事实与语言

- 事实、解读、比喻、模拟示意分开。关键断言核对原始来源，数字写单位、分母、时间与适用边界；引用逐字核验。
- 一句一个可消化的信息单元。中文扫描用于找疑点，不是替代编辑；不按三幕配额硬塞术语。
- 不强制旁白。有旁白时，字幕、解说与图形各自分工；无旁白时，`narration` 存主要屏幕解说。不把正文再在图上重复一遍。
- 比喻可以引入问题，但不能充当机制证据；科学结论不能直接外推为人生定律。

### 沿用机器契约，不增加无人消费的字段

`assets/templates/shotlist.template.json` → `spec/shotlist.json`。每镜保留现有字段：

- `dur_s / narration / visual / tool / source_note`：`visual` 写**主体、初态→变化→结果、观众由此能理解什么、与前后镜如何接上**。跨句连续演示可跨多个 shot 共用主体；shot 边界不强制视觉重置。
- `camera_move: allowed | forbidden`：说明有意运镜，不能把相机漂移当信息推进。
- `motion.kind / intent / maxHoldS`：`intent` 写变化的理由、关键时点／帧与结果停留；有意静止也写原因。细则见 [MOTION.md](MOTION.md) §1。
- `known_gaps`：只列实际未核实项与处理方式，不能为填满字段编造问题；未评审时写清未评审。

过分镜前问三句：**画的是什么？发生了什么？观众因此明白什么？** 把图换成别的选题仍然通用的粒子背景，不是机制演示。命名、引用、必要阅读页可以不动，不强行配动画。

`STORYBOARD.md` 由 shotlist 与时间线生成，不手工维护第二真源。当前生成器会硬写 `status: animated`，也不投影所有检查字段：**生成成功或这个状态文字都不是审批凭证**；实际审批只认 `review_log.md`。v9.1 仅修正跨盘项目的工具来源路径显示，未更改状态语义或审批机制。

### 项目级时间线适配：进入生成器前的必需接线

**本仓库没有适配所有新项目的自动排时器。** `scripts/build_timeline.mjs` 是旧配音转换器：读 `assets/audio/timing.json` 与镜头 `start_s`，只写 `remotion/src/data/timeline.ts`，不读 duration_plan、不产 beat_timeline。不能把它直接用于只有 `dur_s` 的当前模板，也不要伪造配音文件或 `start_s` 蒙混。

续做采用项目已有、已经验证的生成入口；新项目在 S3 按当前授权实现项目级适配器，并在项目现状中记下入口和命令。输入为已批准的 shotlist、duration_plan，以及该片确需的配音实测或音乐网格；输出为 `spec/beat_timeline.json` 与渲染器消费的时间线，两者来自同一次排时。适配未完成就标“时间线待实现”，不能跳过到样片渲染。仅做文稿／分镜构思时不必提前造渲染工程。

最小的**已排时中间契约示例**如下，不是所有片子的固定节奏，也不是应手工长期维护的第二真源：

```json
{
  "fps": 30,
  "duration_s": 9.2,
  "film_frames": 276,
  "shots": [
    {"id": "s00_example", "start": 0, "dur": 126, "lines": [1]},
    {"id": "s01_example", "start": 126, "dur": 150, "lines": [2]}
  ],
  "lines": [
    {"i": 1, "shot": "s00_example", "text": "观察两条轨迹", "start": 6, "end": 120},
    {"i": 2, "shot": "s01_example", "text": "比较分叉结果", "start": 132, "end": 270}
  ]
}
```

适配器必须核对：

- `fps` 与 shotlist／duration_plan 相同，`film_frames = duration_plan.frames`，`duration_s = film_frames / fps`；渲染器的 `FILM_FRAMES`、镜头与字幕也保持一致。shotlist 的秒数是设计输入，最终整数帧排时须回查总预算，不默默截掉尾镜。
- 镜头 ID／顺序对应 shotlist，`start` 从 0 连续，`dur` 为正整数，末镜终点等于 film_frames；`bar` 还须对齐实际小节网格。示例 `lines` 是字幕 ID 列表，无字幕镜为空列表。
- 字幕 `i` 唯一，`shot` 对应所属镜头，`text` 与该镜 narration 按换行拆分后的顺序一致；时间为整数帧，使用 `[start, end)`，正时长、不重叠。既有审计还要求同镜相邻字幕至少间隔 1 帧（`next.start > prev.end`，端点相接也会报错），且字幕在镜头首尾各留至少 2 帧；跨无字幕镜延续使用已有 `caption_hold_bars` 约定，不代表任意跨切点字幕已经兼容。
- 项目工程须实现每个镜头。现有 `audit_music_cut.py` 还按 `Film.tsx` 的 `case "镜头ID"` 和 `timeline.ts` 的导出文本检查覆盖，并假定有字幕行；其他组件结构或纯无字幕片要先适配检查器，不能把异常当通过。

在临时数据／样片工程上验证映射后，再调用 `make_storyboard_md.py` 和适用的审计工具。生成 storyboard 只能证明这部分字段可读，不能证明 renderer 接线、事实或审批已经完成。

## 4 · S4 设计 → S5 素材

- **默认视觉实验／连续演示**：具体主体、同一把尺子、稳定颜色含义、可见的关系变化。可以是曲线、实物、地图、文字或示意模型，不必装进纸／屏／灯箱。
- **纸面档案是可选路线**：当原始文献、历史材料、记录的可信感确实有用时选择；不为每句话添加标题、脚注、印章和重复字幕。
- 一次一个视觉焦点，不是机械限制元素总数。比较可以并排，多对象可共同展示一个关系；背景和标签只保留理解所需的部分。
- 暗场、亮场、留白、彩色强调都可用。颜色、发光、质感必须有目的；不强制黑底金字、英文小字或粒子。首帧和独立投稿封面分开设计。
- `frame.md` 的 frontmatter 是颜色、字号、间距与缓动的规范值，要与源码主题一致。信息字必须在实际手机尺寸可读；不能靠质感小字承载论据。
- 真实数据／资料优先，生成图与模拟标注示意。严谨的几何／数据计算与形象资产可分工，不要求一套模型包办。
- 已有 `BRIEF.md` 与批准配方不重复询问；查现成组件前先确认本机可用和联网权限，不为查外观自动安装。
- 素材按获批的一镜／一场／一段产出。提示词明确、互不依赖的任务可并行，但昂贵批量仍需授权；新风格先小样，固定 seed／参考图以便比较。

## 5 · S6 样片与动效 → S7 装配

### S6 先验证最难的解释，再验证连续开场

1. **关键机制样片**：选最容易误解、最能代表本片的一个单元，以完整画质做出“初态—变化—结果”。先审是否解释成立，再审美术；不是只出一张漂亮海报。
2. **开场连续样片**：把承诺、例子和第一次兑现连起来，通常用前 10–30 秒作为内部工作单元，按内容可调整；这不是平台推荐门槛。如果代表镜就在开头，可复用，不必重复建造。
3. **分别审查**：静音并暂遮解说层，看机制关系是否由画面表达；单读文稿，看结论是否准确；手机尺寸 1× 连播，看注意力、阅读和声音是否打架。遮字检查不是要求所有命名／引用页无需文字。
4. **记录并等确认**：在 `review_log.md` 写片段版本、时间范围、问题、改动、审查人、已看／未看维度和批准范围。点头后也只按批准段落展开，不自动批量铺全片。

动作时点由因果、阅读与声音决定，不统一塞在镜头 55–70%。一个因果过程可以有多个相继步骤；不规定每句换卡。运动后保留足够的观察时间；阅读字幕稳定，作为演示对象的文字可以按设计变化。

### S7 装配

- 时间线由 `duration_plan.json` 与 `shotlist.json` 驱动。`bar` 按小节契约，`caption` 按内容／句子契约；不能在装配时悄悄切换。
- 字幕用现有 `Caption` 契约。1080×1920 既有配方：右端 ≤920，**距底 ≥360 px**；其他画幅或平台重新测 UI 与阅读尺寸，不能直接套像素值。
- 用户自备配乐不替换、不代找、不用生成曲或 TTS 顶替。是否有人声、是否去人声按 brief 执行；无音乐时可先交明确标注的无音轨版。

```bash
# remotion：音床置于 remotion/public/audio/，再进入最终渲染
bash <tools>/mix_music.sh <film.mp4> <track> [out.wav]
bash <tools>/mix_audio.sh <film.mp4> <track> <narration.wav>

# post_mux：静音母版 + 等长音床 → 视频流 copy
bash <tools>/mux_music.sh <silent.mp4> <bed.wav> <out.mp4> [bitrate]
```

`mux_music.sh` 检查音床长度（±0.05 s）、视频流 md5 不变、音轨起点／时长、faststart，并在交付 AAC 上量响度。只量 WAV 不算交付。post_mux 每次重渲都必须重新封装。

音乐收尾按曲式与实际听审处理；现有混音配方的尾部淡出与静音余量见 [LESSONS.md](LESSONS.md) §2，不照搬到所有曲子。音效只标注必要事件，不用音效遮盖讲解缺口。

渲染走 `scripts/render.sh`：端口预检、默认并发 1、带外 CPU 采样；缺本地 CLI 时停止，不自动 npx 下载。静帧不采样，视频结束只清理本次仍在运行的采样子进程，不按进程名结束其他任务。CSV 按输出文件名标签写入 build，同项目同标签会覆盖，需先留存上次报告并避免同标签并行。CPU 目标 ≤80%，开环并发不是保证，每次都报 over80 样本数／总样本数。不要 source 会导出 `OMP_NUM_THREADS=1` 的通用环境文件。

## 6 · S8 评审 → S9 交付 → S10 收尾

### S8-A 内容与连续观看（人工门禁）

先审关键机制和开场，再审获批扩展段，最终审全片。记录精确时间范围与版本：事实是否能溯源；开头承诺是否兑现；主体与尺度是否连续；哪里需要暂停才能懂；哪里只有字幕在讲、画面没解释；结尾有没有引入未经支持的新结论。

在实际手机尺寸 1× 连播与听审；切点前后各 6 帧、运动落点、文字峰值画面另抽查。静帧看构图，连续片段看节奏，完整音轨听接缝——互不冒充。工具／页面不可播放时，记录“未连播／未听审”，不能写终审通过；交给能够完成该项的创作者确认。

### S8-B 技术检查：机器真判与报告项分开

`scripts/gates.sh` 会调度以下项目，但**不是所有工具都能以退出码表达质量问题**。本表原以提交 `4f2ab18` 的测量工具源码为核对基线；v9.1 调整启动与采样封装。v9.2 提交 `7909bb0` 已改动安全区／压字检测，下表该行按本次源码复核更新，其余项目仍沿用已注明的历史基线。**源码复核不等于新成片实测**，不能把旧报告用于新文件。

| 项目 | 已核对的自动行为 | 必须怎样验收 |
|---|---|---|
| 素材结构 `plate_gate.py` | 已接入 FAIL | 在工具覆盖的组件内检查切片需求与可用帧；其他管线另补检查 |
| 响度／音轨 | −14±0.5 LUFS、TP≤−1，缺少声明应有的音轨会 FAIL | 本地产线目标，不冒充平台统一强制标准；在最终文件测量 |
| 音画／封装 | 起点、声画等长（约 1 帧容差）、faststart 接入 FAIL | post_mux 传 `--video-md5` 才核对静音母版；不传只打印摘要 |
| `motion_energy.py` | 最长静止超过声明上限加 0.05 s 容差会 FAIL；能量与全片静止占比会 WARN | 仅验证像素变化与声明，不能判理解／审美；看完整日志里的 WARN |
| `audit_music_cut.py` | 退出码接入 FAIL；`bar` 强判，`caption` 只报告小节偏差 | 核对模式、音乐网格和时间线；不得伪造音轨文件过关 |
| `luma_report.py` | **仅打印**亮度带、切点台阶、下陷、首帧等；无亮度越界退出码 | 人工标注疑点并连播复核；>25 是筛查线，不是暗场禁令 |
| `plate_swing.py` | **仅打印**镜内摆幅／跳变；当前只遍历雨片固定镜头 ID | 换项目不能称覆盖全部素材；补查实际镜头，人工确认回卷 |
| `safezone_check.py` / `text_zone_check.py` | **仅打印**亮字边界／疑似压字；v9.2 增加面向 1920×1080 的固定像素分支，无质量失败退出码 | 按宽高分支，不验证画幅、不随分辨率缩放；其他尺寸先适配。亮字与固定字幕带假设须人工复核，不能据此声称实际平台 UI 安全 |
| `text_right_edge.py` / 中文扫描 | 源码估算／文案提示；当前总控没有可靠汇总其失败 | 人工核字号、文字与事实；扫描器缺失记未覆盖 |
| CPU 采样统计 | 打印 over80；缺文件汇总 WARN，不按超限样本自动 FAIL | 逐次报告样本数与峰值；超限不能写“资源合格” |

**横版分支的具体边界（v9.2 源码复核）**：`safezone_check.py` 对 `width >= height` 固定使用右界 1680、底界 980，并只扫描下半屏；`text_zone_check.py` 对同一分支使用右界 1680、压字扫描起点 850，不执行底界 980 判定。白字所在行附近的排除带还可能漏掉同区灰字。正方形和其他横版分辨率也会误入该分支，空扫描区可能报错；没有有效亮字样本时，安全区脚本也可能报错。以上均不是通过。本次只查源码，未验证这些坐标对应当前抖音 UI；即便采用 1920×1080，也仍需在实际观看状态复核。

**总控最后的“所有闸门通过”只表示它接入的失败项未触发。** 不能据此把仅报告项、漏检项和人工审片涂绿。缺日志、没覆盖的镜头、工具错误均不能当通过。迭代可用 `--allow-silent`；交付时去掉它，真正无音轨项目声明 `audio.mode: none`。

在项目 `review_log.md` 记录技术判定：文件版本、原始报告、工具覆盖、人工复核结论、未解决项。报告项人工待审也会阻止“可发布”结论；不需要伪造统一 0 FAIL。本次文档勘误未修改数值工具，未来若补自动判定，须单独设计与测试。

### S9 交付

交付成片路径、最终文件实测、真实迭代轮数、审查覆盖、剩余 WARN／缺口；更新 `STATUS.md`。如需投稿，`outputs/publish/publish.md` 是唯一投稿入口，放成片、独立封面、发布文案与平台检查状态，历史移到历史分区。

首帧要有可辨识的主体／信息，不用无信息黑屏让人等待；**整帧平均亮度 >60 不是通用要求，视频首帧也不等于所有展示位置的封面**。独立封面按当前投稿界面验证尺寸、满幅、裁切和文字；过往 3:4＋4:3 要求是具体入口的实测，不是所有平台规则。上传／发布须有对应授权。

平台侧再核对三件本地闸门测不到的：描述在**折叠状态整体读一遍**（尾部与话题计数尤其要看）、话题**实体逐个回读**（本次抖音入口曾把粘贴的标签规范化成别的词条）、封面自检结果。2026-10-29 的抖音实操在审核期间遇到禁止修改提示；不能推广为多数平台的统一规则，也不能依赖提交后补救。**提交前完成可见页面的最后核对；无法核验时停在待确认，不盲发。** 具体工具与隐藏面板的经验仅适用于当时环境，见 LESSONS §4.6–4.7。

已有可用 recipe 工具时，批准后可冻结配方；不把未完成连播、未验证效果的风格包装为“成功配方”。

### S10 收尾：回灌 → 升版 → 自查 → 按授权提交／推送

创作者定稿后及时收口，不把教训留在聊天里。**定稿、提交、推送、发布是不同授权**：当前明确只提交就不推送；有覆盖本次的明确推送授权才推，不能从“定稿”自动推导对外发布权限。

1. **回灌**：实测注明文件版本与报告；研究注明来源与覆盖；推论标明待验证。改当前数字先重测，旧测量保留历史标签。规则放本文／MOTION，根因放 LESSONS，不制造第二个现状入口。
2. **升版**：规则或契约改变才升版，§13 写原因与验证边界；修措辞不用另起版本。
3. **项目收口**：只更新本轮获准项目的 STATUS／投稿入口，不借流程升级改旧片。
4. **Git 自查**：检查完整状态、已暂存与未暂存 diff、新文件及最近提交风格；已有无关改动保留原样，不为清洁状态删文件。

   ```bash
   git status --short
   git diff
   git diff --cached
   git ls-files --others --exclude-standard
   git log -5 --oneline
   ```

   项目私有目录、自备 BGM 与派生音频、个人路径、凭据、生成媒体、构建产物不得进入本次暂存。状态里有用户原有未跟踪文件不等于必须清理。
5. **按授权提交／推送**：`git add <逐个点名的本轮文件>`，不用 `git add -A` 或 `git add .`。中文说明“为什么”；用 HEREDOC 传消息，新建提交，不擅自 amend。hook 失败先修原因；不改 git config、不跳 hook／签名、不做未经批准的破坏性操作。仅提交的任务到此为止。
6. **回报**：提交后 `git status`；短哈希、核心变化、已推送／未推送与验证缺口。没推送就明说，不把本地提交当远端成功。

## 7 · 指标边界与异常处理

- **帧差不是语义**：默认缩到 270 px 宽灰度、冻结线 0.10。细线运动可能低于阈值，装饰性色块却很容易过线。两者都不能证明观众是否理解。取消“细线必须补章”的规则，处理步骤见 [MOTION.md](MOTION.md) §9。
- **亮度不是审美**：YAVG 是全帧平均值，不能描述局部字的对比、细小闪烁或颗粒。切点均值差 >25、镜内跳变 >4.0 是历史筛查信号，先定位再连播；区分故障、刻意揭示和正常实拍，不压平所有明暗变化。
- **不能悄悄改声明抹掉 FAIL**：保留原报告，先复现并判断故障／测量局限。确需更改既有 `maxHoldS`，写出该镜阅读或观察任务、时长依据、人工审查人与范围，再重测。未解决项保持失败／待审，不改成片“刚好过线”。
- **安全区不是 OCR**：现有脚本按亮度与边缘筛选，可能漏掉暗字或把亮底当字；`text_zone_check` 的“带内文字”也未证明与字幕实际重叠。最终按画幅、真实 UI、实际阅读状态核对，不能以一次中点采样替代全程检查。
- **声明与覆盖要分开**：`camera_move`、`motion.intent` 是人工设计依据，不等于已有脚本自动理解；素材固定 ID 检查不得推广为任意项目完整覆盖。
- **像素格式按实测解释**：历史产物为 yuvj420p（full range / bt470bg）。不为改标签盲目二次转码；有色彩异常先查范围／播放器解释，再决定修复，不保证所有新片颜色天然正确。

## 8 · 从现成方法借什么、不借什么

1. **形象与讲解共同设计**：借鉴具体对象、同主体演进、先做最难解释与连续开场；不复制参考片的文案／图形，不把它的画幅、无旁白、时长或转场配额变成普适规则。
2. **图像与代码分工**：图片提供形态，代码提供精确状态与关系；不换掉已能满足需求的 Remotion，也不假称第三方引擎已安装或跑通。
3. **尽量减少有损代际**：能在最终装配一次完成的裁剪／叠字／调色合并处理；必要中间资产说明编码链。后期只加声音就 stream copy，不为口号强制所有管线一条 ffmpeg 命令。
4. **静帧与连续片段互补**：参考总览可稀疏抽帧，动作交接必须看片段。analyze-video 的粗采样方法不能用于证明无闪帧；剪辑前先核 rotation 元数据再判断横竖屏。

## 12 · 禁用清单

为过帧差线补章、脉冲或微动；无信息的整帧缩放漂移；每镜重置为一张新卡再淡入淡出；用装饰背景替代解释；文字与多个无关动作抢同一时刻的注意力；把比喻当数据分母或科学结论；有意省略关键限定；将独立封面检测当视频亮度规定；把平均观看时长／片长叫完播率；未经授权下载执行、安装、上传、推送或发布。

不是禁用某种颜色、暗场、细线、纸张或静止；禁的是**没有信息目的、没有证据和没有授权**。动效细则见 [MOTION.md](MOTION.md) §11。

## 14 · S11 发布后复盘与本轮研究依据

### 发布后复盘：用自己的数据检验假设

发布需单独授权。没有后台权限时向创作者取导出或截图，不伪造数据、不把公开点赞当留存。项目 `STATUS.md` 只留当前结论与下一次验证；原始截图／数据留本地，历史复盘另分区。

可约定发布后 **24 h / 72 h / 7 d** 复看，作为工作安排而非算法起量节点。每条记录：作品版本、时长、发布时间、采集时间／发布年龄、自然或投放流量及来源、原字段名／单位／分母、原始证据。缺字段记缺失，不填估计值。

- **开头**：后台确有 2 秒跳出／5 秒留存等字段才记录，并保留其当前解释，不能凭名称猜公式。
- **机制段与结尾**：有留存曲线时把下降段映射到准确时间与内容；无曲线不倒推“某一镜导致流失”。平均观看时长／片长仅是归一化观看时长，**不是完播率**，重播还可能使它超过 1。
- **理解与价值**：归纳评论中的复述、疑问和误解，但承认评论者自选择偏差；分享、收藏、关注须有同口径分母才能算率。帐号新增粉丝不全归给某条作品，也不等于净增。
- **下一轮试片**：尽量匹配题材、片长、帐号阶段、流量来源与观察年龄，只改一个主要变量（例如开头是否先做预测，或机制是否同主体连续演示）。自然流量比较不是随机 A/B；少量试片只筛方向，不宣称因果或统计显著。不为实验重复刷发同一条。

复盘结论按“观察 → 竞争解释 → 下一条验证”写。没有数据时状态为**发布效果待验证**，不阻止本地文件交付，也不允许宣称已优化留存。
