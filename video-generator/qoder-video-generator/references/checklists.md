# 三张清单

命令中的 `<tools>` 指 `tools` 的绝对路径；在项目根目录执行。

## 一、开工

- [ ] 读当前 `WORKFLOW.md` 版本与项目 `BRIEF.md`、`STATUS.md`、`review_log.md`，确认本轮授权范围与未授权项。
- [ ] 明确观众带走的一个结论、片长档位、声音路线（自备 BGM / 无音轨 / 配音）与画幅。
- [ ] 若改动结构：先算帧账（时长 × fps），确认主角段 ≥ 50%、每章一个问题、一行字幕一镜。
- [ ] 先改 `spec/shotlist.json`，再生成 `beat_timeline.json`、`duration_plan.json`、`timeline.ts`；`STORYBOARD.md` 只用工具重生成。
- [ ] 分镜里每个画面动作都能在源码里指到；不确定的画法先降为注脚或删掉。
- [ ] 跑项目测试（时间线、字幕契约、产物与源一致、几何）；旧片与无关项目不动。
- [ ] 只保留一个现状入口（`STATUS.md`），历史版本单列。

## 二、开渲前

- [ ] 每个新镜先出**单镜满画质 look-dev 静帧**，逐镜实际打开看；不要等全片渲染后才发现。
- [ ] 亮图版检查层级：墨罩在图版之上、标注之下；在**全亮帧**量标注与图版的最大/平均亮度（目标：标注明显更亮，本片 238–240 对 120）。
- [ ] 不要用闸门静帧判断层级：静帧可能取在淡入中途。要另取镜内末段全亮帧。
- [ ] 检查切点台阶与下陷：亮承载物进入前先量前后镜均值；超过 25 luma 就压，不靠淡入淡出。
- [ ] 检查场景文字右端（16:9 用 `railX=1640`；9:16 的 920 不适用）与字幕带边界。
- [ ] 确认端口 3134 空闲；并发保持 1；渲染走 `render.sh` 以生成 CPU 采样。
- [ ] 首帧有可辨识主体；问题在 0.2 秒内出现，2–3 秒第一次兑现。

## 三、交付

- [ ] `gates.sh` 跑在静音母版上并保留完整 `console.txt`；退出码不等于全部质量。
- [ ] 交付带音轨时：`mux_music.sh` 封装，确认视频流 md5 与静音母版一致、音频起点 0、等长、faststart。
- [ ] 在交付 MP4 上重测响度（−14 ± 0.5 LUFS、TP ≤ −1）、逐 cue 平衡（+3 / −1 dB 门槛）与对位（≤ 5 ms）。
- [ ] 安全区与字幕带用 `gates.sh` 的扫描结果，并记录实测像素（离底、离右、最低、最右）。
- [ ] 报 CPU 样本数、mean、p95、max、over80；缺采样写“未验”。
- [ ] 更新 `STATUS.md`（当前文件、字节、md5、时间、已验证项、未验项）与 `review_log.md`（缺陷、修正、失败原样保留）；`shotlist.json` 的交付路径同步。
- [ ] 旧版本保留并标历史，不删；新版本名与替换原因写清。
- [ ] 未做 1× 连看、听审、手机尺寸、平台 UI、封面、传播就逐条写“未验证”。
- [ ] 提交、推送、上传、发布各自单独授权；没有授权就停在本地。

## 四、审片（人工，机器不能代替）

- [ ] 1× 连续观看：开头 3–5 秒是否抓住；哪里需要暂停才懂；哪里只有字幕在讲、画面没解释。
- [ ] 听审：音乐是否压字幕；音效是否吵；闪避是否像音乐在“喘”；接缝能否听出。
- [ ] 手机尺寸阅读：最小字号与最亮标注是否仍清楚。
- [ ] 当前平台 UI 安全区与封面自检（折叠描述、话题实体、封面裁切）。
- [ ] 把上述结论写进 `review_log.md`，不与技术闸门混写。
