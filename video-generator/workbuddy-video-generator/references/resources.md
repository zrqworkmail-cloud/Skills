## 技能本体放哪

- **仓库副本**：仓库根目录本身（`SKILL.md` + `scripts/` + `references/`，进 Git，管版本）
- **用户级副本**：`~/.workbuddy-ai/skills/workbuddy-video-workflow/`（运行时实际加载的）

技能名 hyphen-case 小写，且必须与 frontmatter `name` 一致（skill-creator 校验要求 `^[a-z0-9-]+$`）。两份各存一份，**改完必须同步、`diff` 无差异才算完**。

产物目录 `out/` 靠 `.gitignore` 挡在库外，规则写 `out/` 而**不带前导斜杠**——带斜杠只匹配仓库根那一层，目录一挪就漏，几百 MB 产物会被提交并让推送整次失败。

## 维护判据（改这份 SOP 时用）

- **主干按阶段写，不按视频类型分章**。按类型分章会让每章重复"选题 / 质检 / 发布"，篇幅翻倍还互相矛盾，而且流程会顺手绑死某一支的工具链——换个项目就得重写。素材路径是「阶段 3」的选项，不是章节。
- **本文不出现项目特定的路径、脚本名、分辨率**。改完 `grep` 一遍项目名与脚本名，命中数应为 0；确实要举例，写明"示例，换项目替换"。一次性数据（镜号、具体秒数、本片参数）只进项目的 films 目录，不进这里。
- **返工复盘按根因归类，不按修改条目罗列**。几十条修改按条列完没人读第二遍；归成 9 类根因、每类给"用户原话 → 为什么第一版会错 → 设计时该问什么 → 修法"，才能变成开工前能用的清单（见 `retro-lessons.md`）。
- **正文守住长度上限（约 5k 词），超了就拆**：深度内容进 `references/` 按需加载，正文只留阶段主干 + 判据 + 索引。塞满正文的结果是加载时被截断，读者拿到的是一份半截流程。
- **文件按角色分目录**：可执行代码 `scripts/`、手册 `references/`、**产出用素材 `assets/`**。素材放包外层目录，下一次同步会被整个冲掉（音源母版曾经因此没进库，换机就丢）。
- **改名是三处联动**：frontmatter `name`、目录名、文档内引用，一起改；目录名与 `name` 不一致时，旧目录会被当成另一个技能加载，盘上并存两套规则。

## 公开镜像（想分享给别人时）

私有仓是源，公开仓只是快照，用 `git archive HEAD | tar -x -C <公开仓>/<领域>-generator/<平台>-<领域>-generator` 单向导出，**不要用 submodule**（公开仓引私有仓，别人 clone 拉不下来）。公开前必须清掉本机绝对路径：Python 用 `sys.executable`、临时目录用 `os.tmpdir()`、浏览器路径走环境变量、文档里的命令示例改成相对路径，然后 `py_compile` + `node --check` + 全仓 grep 验证。注意本地路径有两种写法都要查：`C:/Users/...`（Windows）和 `/c/Users/...`（Git Bash）——只清一种会得到"已经清理过"的假象。

同一份清单还要清**身份信息**：提交身份、脚本署名里的真实姓名与邮箱走环境变量兜底（`GIT_NAME` / `GIT_EMAIL`），代码里只留占位。

**快照按内容校验，不按文件数。** 源仓每天自动提交，快照不会自己跟上来——文件集合一致也可能有好几个文件停在上一版，同步后逐文件 `cmp` / `diff -r`。

**命名统一 `<领域>-generator`**，不用 `production` / `-skill` 后缀；同层级出现三种命名，读者找不到规律。**旧仓 archive ≠ 删除**：归档只是只读，URL 与内容仍公开，彻底删除要额外 `delete_repo` 权限。本地移除 remote 后仓库就是纯本地源，`git push` 无处可去，此后唯一出口是快照同步。
